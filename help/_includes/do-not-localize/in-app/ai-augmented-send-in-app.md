# AI Knowledge Reference

+++ AI Knowledge Reference

This section contains structured knowledge intended to support interpretation, retrieval, and question answering related to this topic.

For complete understanding, this information should be combined with the documentation on this page. Neither source is intended to stand alone; the page describes the feature, while this section provides additional context that helps disambiguate terminology, intent, applicability, and constraints.

* **TL;DR:** This page explains how to preview, test, review, and activate an In-app message in Journey Optimizer before it is sent to your audience.

**Intents:**

* Preview the In-app notification on a specific device using Preview on device
* Preview the message using Simulate content with sample input data or AI auto-generation
* Preview with test profiles using Simulate content (AEP profiles)
* Review the message summary and activate the campaign
* Understand when the In-App notification is sent and where to measure its impact

**Glossary:**

* **Preview on device**: A function that lets you trigger and preview the In-app notification on a specific physical device by connecting via a Base URL, QR code scan, and PIN code *(product-specific)*
* **Simulate content**: A method to test content variations with sample input data or AI auto-generation *(product-specific)*
* **Simulate content (AEP profiles)**: An option selected from the Simulate content dropdown to preview with test profiles by adding a test profile to check your message *(product-specific)*
* **Review to activate**: A button that displays a summary of the message so you can modify the campaign and check for incorrect or missing parameters *(product-specific)*
* **Approval policy**: A policy that, when a campaign is subject to it, requires you to request approval before you can send the In-App notification *(product-specific)*

**Guardrails:**

* If your campaign is subject to an approval policy, you must request approval before you can send the In-App notification.
* Once activated, the In-App notification is sent immediately, or on the specified date.

**Terminology:**

* Canonical name: In-app notification — Acronym: n/a — variants: In-app message, In-App notification
* Synonyms: "Preview with test profiles" = "Simulate content (AEP profiles)"
* Do not confuse: "Preview on device" (preview on a specific physical device) ≠ "Simulate content" (test content variations with sample input data or AI auto-generation) ≠ "Simulate content (AEP profiles)" (preview with test profiles)
* Do not confuse: "Review to activate" (display the message summary) ≠ "Activate" (activate the campaign to send the notification)

**FAQ:**

* **Q: How do I preview the message on a real device?** — Click Preview on device, start the connection, enter your application Base URL, then scan the QR code and enter the displayed PIN code to trigger the message on your device.
* **Q: What is the difference between the two simulation options?** — Simulate content tests content variations with sample input data or AI auto-generation, while Simulate content (AEP profiles) previews with test profiles by adding a test profile.
* **Q: What does Review to activate show?** — A summary of your message that lets you modify the campaign and check whether any parameter is incorrect or missing.
* **Q: When is the In-App notification sent after activation?** — Immediately, or on the specified date.
* **Q: Do I always activate directly?** — If your campaign is subject to an approval policy, you must request approval before you can send.
