# AI Knowledge Reference

+++ AI Knowledge Reference

This section contains structured knowledge intended to support interpretation, retrieval, and question answering related to this topic.

For complete understanding, this information should be combined with the documentation on this page. Neither source is intended to stand alone; the page describes the feature, while this section provides additional context that helps disambiguate terminology, intent, applicability, and constraints.

* **TL;DR:** This page explains how to use the auto-synced default plain text version of an email or create a custom one by disabling sync, and when each approach works best.

**Intents:**

* Access the default, auto-generated plain text version of an email
* Create and edit a custom plain text version by disabling synchronization
* Decide when to use custom plain text versus auto-sync
* Understand how personalization fields behave in the plain text version
* Test the plain text version

**Glossary:**

* **Plain text version**: A text version of the email body, used when HTML content cannot be displayed *(product-specific)*
* **Default (auto-synced) plain text**: The Plain text version the Email Designer generates automatically, including personalization fields, and keeps synchronized with the HTML content *(product-specific)*
* **Sync with HTML**: The toggle that enables or disables synchronization between the Plain text and HTML versions *(product-specific)*
* **Custom plain text version**: A plain text version you edit independently after disabling Sync with HTML *(product-specific)*

**Guardrails:**

* When synchronization is disabled, changes made in Plain text view are not reflected in HTML view.
* If you re-enable Sync with HTML after updating your plain text content, your changes are lost and replaced with text content generated from the HTML version.
* If you do not create a plain text version, the system automatically generates one from your HTML, which may not be optimally formatted but ensures delivery to text-only clients.
* Plain text does not support images; describe what the image shows or link to view it online.
* Personalization fields work identically in both HTML and plain text versions; once sync is disabled you can use different personalization in each.

**Terminology:**

* Canonical name: text version of an email — Acronym: n/a — variants: plain text version, Plain text, custom plain text
* Synonyms: "auto-sync" = "Sync with HTML enabled"
* Do not confuse: "default (auto-synced) plain text" (generated from and synchronized with HTML) ≠ "custom plain text version" (edited independently after disabling sync)

**FAQ:**

* **Q: How do I create a custom plain text version?** — Select the Plain text icon, use the Sync with HTML toggle to disable synchronization and confirm, then edit the custom plain text as desired.
* **Q: What happens to my custom text if I re-enable sync?** — Your changes are lost and replaced with text content generated from the HTML version.
* **Q: Do personalization fields work in plain text?** — Yes; personalization fields work identically in both HTML and plain text versions.
* **Q: What if I forget to create a plain text version?** — The system automatically generates one from your HTML, ensuring delivery to text-only clients.
* **Q: When should I use custom plain text instead of auto-sync?** — For complex HTML layouts, visual-heavy content, a different messaging structure, accessibility requirements, legacy email clients, or specific ASCII formatting.
* **Q: How do I test my plain text version?** — Toggle to Plain text view in the Email Designer, and send test emails to text-only clients.
